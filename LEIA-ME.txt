A MESA — ORGANIZADOR DE EMENTAS
Versão 4 — 13 de novembro de 2026
================================

PEDIDOS NA PRÓPRIA PÁGINA
Os pedidos são consultados em A cozinha → Pedidos.
Não existe envio de email, serviço de notificações, botão de reenvio ou
configuração de destinatário nesta versão.
O registo de um pedido só o guarda para consulta no painel da cozinha.

Cada dia apresenta dois números grandes, lado a lado:
- Almoços à esquerda, a verde.
- Sobremesas à direita, a roxo.

As contagens de sobremesas incluem os pedidos sem almoço.
A secção "Sobremesas por preparar" continua a separar as doses por sobremesa.
Use "Atualizar pedidos" para obter os pedidos mais recentes.

MANTÉM-SE
- Pedidos só de almoço, só de sobremesa ou de ambos.
- Quantidades independentes, de 1 a 99 doses.
- Duas opções de sobremesa por semana.
- Alergénios por prato e sobremesa.
- Nome e observações, sem contacto e sem valores monetários.
- Código da cozinha definido na versão 3 e botão Mostrar/Ocultar.
- Logótipo e fundo preparados para uma futura alteração.

EXPERIMENTAR
Abra index.html no navegador.
A faixa "Demonstração" identifica o modo local. Os testes só ficam na sessão
desse navegador; outras pessoas ou dispositivos não os veem.
A prévia tenta recuperar a ementa e os pedidos das versões 2 e 3 que existam
na mesma sessão e origem.
Entre na cozinha e abra Pedidos para consultar os testes.

PARA A EQUIPA USAR
As pessoas usam a mesma página para escolher as refeições, e a cozinha
consulta os pedidos no separador reservado.
A ligação ao servidor guarda a ementa e os pedidos partilhados entre os
dispositivos. Não exige email. Só o HTML no GitHub mantém o modo demonstração
enquanto API_URL estiver vazio.

ATUALIZAR UMA INSTALAÇÃO EXISTENTE
1. Guarde uma cópia dos ficheiros anteriores.
2. Conserve o seu endereço API_URL no novo index.html, caso já esteja definido.
3. Atualize os dois ficheiros da pasta servidor:
     worker.mjs
     validation.mjs
   Preserve o seu wrangler.toml com a base de dados e ALLOWED_ORIGIN atuais.
4. Na pasta servidor, publique a nova API:
     npx wrangler deploy
5. Substitua o index.html no GitHub.
6. Faça um pedido de teste e confirme que aparece em A cozinha → Pedidos.

É necessário atualizar também o servidor para remover o envio da instalação
publicada. A nova página recusa uma API anterior a esta versão, para impedir
que use um servidor antigo ainda capaz de enviar notificações.

Não elimine nem recrie a base de dados. Os pedidos anteriores continuam
disponíveis, sem estados ou opções de email.
As antigas configurações de email, se existirem no servidor, são ignoradas
pelo código da versão 4. Não são necessárias configurações novas.

CONFIGURAR PELA PRIMEIRA VEZ
O GitHub Pages apresenta a página. O servidor incluído corre num Cloudflare
Worker e guarda a informação numa base D1.
Este pacote não cria contas nem ativa os serviços automaticamente.

Requisitos: conta Cloudflare e Node.js com npm.

Na pasta servidor:
  npx wrangler login
  npx wrangler d1 create a-mesa

Copie o database_id devolvido para wrangler.toml.
Em ALLOWED_ORIGIN coloque só a origem do seu GitHub, por exemplo:
  https://seunome.github.io
Não inclua o nome do repositório nem uma barra final.

Crie as tabelas:
  npx wrangler d1 execute a-mesa --remote --file=schema.sql

Configure o código da cozinha:
  npx wrangler secret put ADMIN_CODE
Introduza o código escolhido na conversa quando lhe for pedido o valor.
Não escreva o código no HTML, no wrangler.toml ou num repositório público.

Publique:
  npx wrangler deploy

No index.html, altere:
  const API_URL = '';
para o endereço HTTPS do seu Worker:
  const API_URL = 'https://o-seu-worker.workers.dev';

Carregue esse index.html no GitHub.
Entre na cozinha, preencha os pratos, as fotografias, as sobremesas e os
alergénios, assinale "Aceitar pedidos" e publique a ementa.
A primeira instalação começa com os pedidos fechados e sem pratos publicados.

ALERGÉNIOS
Reveja as receitas, os ingredientes e os rótulos dos fornecedores.
Marque as categorias aplicáveis, acrescente detalhes e confirme
"Informação revista pela cozinha".
Uma lista vazia não garante ausência de alergénios.

VERIFICAÇÃO
Foram verificadas as contagens diárias e a gravação/consulta dos pedidos,
incluindo repetição do mesmo envio e pedidos só de sobremesa.
Os serviços externos foram simulados nos testes. Nenhuma ação externa de
envio foi executada. Os detalhes estão em VERIFICACAO.txt.
Não foi possível fazer o teste visual num navegador ou publicar a instalação
nesta sessão.
